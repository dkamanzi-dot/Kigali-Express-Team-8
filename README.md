## Problem

Kigali Express has 10,000 drivers. Every customer request searched the list of drivers one by one, which made lookups slow.

Our fix was to convert the list into a dictionary where the keys are driver IDs. Looking up a driver then takes O(1) time instead of O(N).

## How to run

```bash
python main.py
python main.py --requests 5000
python -m unittest -v
```

The sample data (`data/drivers.json`) is generated by `kigali_express/data.py`. If the file is missing, the program creates it.

## Search methods

**Linear search, O(N):** checks each driver one by one.

**Binary search, O(log N):** splits a sorted list in half each step. The list has to stay sorted.

**HashMap, O(1):** the mapping loop runs once to build a dictionary `{driver_id: driver}`. Each lookup after that is a single step.

```python
def build_driver_hashmap(drivers_list):
    driver_dict = {}
    for driver in drivers_list:
        driver_dict[driver["driver_id"]] = driver
    return driver_dict


def hashmap_search(driver_dict, target_id):
    return driver_dict.get(target_id)
```

## Results

10,000 drivers, 1,000 random requests:

| Method | Setup | Per lookup | Speed-up |
|---|---|---|---|
| Linear Search | - | ~630 µs | 1x |
| Binary Search | ~7 ms (sort) | ~7 µs | ~90x |
| HashMap | ~3 ms (build) | ~0.4 µs | ~1,700x |

Building the dictionary takes about 3 ms and only happens once. Timings will vary from one computer to another.
